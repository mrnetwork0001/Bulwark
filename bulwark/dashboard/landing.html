The bug Bulwark found

Your agent passes its tests. It also just refunded a customer twice.

RefundBot retries refunds because payments are flaky. When a refund commits but the response is slow, the retry pays again. Nothing crashes, no test fails, and the money is gone. Bulwark caught it in 8 of 20 trials, wrote an idempotency-key fix, and proved it on 40 fresh trials.

Traced with Entire to the line that caused it: tools.ts:87, written in Claude Code session 8cdad8b4 from the prompt "start building something for this app".

How it works

Attack. Fix. Prove.

Four agents with separate jobs. The one that writes the fix never grades it. Every step is traced in neatlogs and checkpointed in Entire.

01
RED

Read the code

Finds the weak links: unguarded tool calls, blind retries, unchecked money moves.

  • file:line for every finding
  • Blast radius from Entire Graph
  • Who wrote it, from Entire checkpoints
02
RED

Attack

Injects real-world failures between the agent and its services, in a sandbox, 20 seeded trials per attack.

  • 8 attacks, plus ones Red invents
  • Plain-English business rules
  • Side effects read from the ledger
03
BLUE

Fix

Writes the patch with Claude through 0G, or from a playbook of known fixes, cheapest first.

  • Told exactly how each rule is checked
  • Competing fixes in a tournament
  • Remembers what worked last time
04
JUDGE

Verify

Re-runs every attack on fresh seeds against an isolated copy. Rejected fixes roll back to a checkpoint.

  • Significance test, no regressions
  • Reliability targets (SLOs)
  • Latency and cost overhead
05
GUARD

Prove

Ships a regression test with every fix, and proves it fails without the fix and passes with it.

  • Postmortem per attack
  • PR with before/after evidence
  • Remaining risk, never hidden

Honest statistics

A lucky run is not a fix.

Most agents "prove" a fix with one passing run. Bulwark won't accept a fix until the numbers rule out luck, and it says so when they can't.

What testing one thing at a time misses

It found bugs in the fixes, and in itself.

Each of these is a real run, with its evidence in the repo.

Game day · several faults at once

Every fix passed alone. Together, they ran out of time.

Each fix bounded its own order lookup to 1s × 3 retries. Stacked before a refund, those bounded reads ran past the 5-second deadline in a latency storm. Bulwark added a run-wide time budget; Claude found a leaner fix in one attempt. On 400 trials the same stacking failed 2.25% of the time, too rare for 40 trials to see.
